# 盐田船期监控

按船名或码头航次查询公众船期，保存状态并比较 ETB、ETD 等字段。公众查询无需账号或查询 Token；浏览器用于获取 EdgeOne Cookie。

## 当前功能

CLI 支持单轮查询、循环监控、变更比较及告警。GUI 支持目标管理、监听设置、手动及自动查询、通知渠道和触发策略配置，以及测试推送。

## GUI 目标管理

进入“目标管理”页可新增、编辑、启用 / 停用和删除船名或码头航次。每次操作立即保存到 watchlist.json；没有配置文件时，首次保存会创建配置，无需手工复制模板。

左侧导航收起时显示主页和船舶图标；点击菜单展开后，图标右侧显示“主页”和“目标管理”。

## GUI 监听设置

“监听设置”页提供监听间隔、随机等待上限、查询回溯天数、最大分页、限流重试次数、退避基础等待和浏览器选项。修改后点击“保存设置”；“重新加载”放弃未保存修改并读取文件。查询中暂不可修改设置。

主页点击“开始监听”立即查询，之后每轮结束等待监听间隔加随机等待，再查询下一轮。进度条由满到空表示剩余等待时间，不再表示查询进度；查询中等待条清空。修改配置会重置等待中的倒计时。“立即检查”可提前查询，完成后重新计时。

点击“停止监听”取消下一轮调度，但不强制中断当前请求。最小化后仍监听，真正退出程序后停止；退出时若有后台任务，会先停止监听、显示等待状态，任务完成后自动退出。编辑弹窗打开时暂缓触发自动查询，关闭后若倒计时已到期再执行。配置错误暂停监听，查询失败等待下一轮重试，不并行执行多轮。

监听设置可开启“关闭窗口后驻留系统托盘”（`settings.close_to_tray`，默认 `false`）。开启后关闭窗口仅隐藏界面，已有监听、倒计时与通知继续；单击或双击托盘图标、或选择“打开窗口”恢复界面。“退出程序”才真正停止程序：停止自动监听，等待当前查询或测试推送完成后退出。关闭此设置时关窗正常退出。托盘不可用时不隐藏窗口。该功能不自动启动监听、不创建 Windows 服务，也不设置开机自启。

Win10+ 托盘图标根据系统深浅主题显示白色或黑色，并在驻留开启时每两秒检测主题变化。Win7 不启用现代主题检测或轮询；读取失败时保留原图标。着色仅在内存中处理，不修改 SVG 文件，也不跟随应用自身主题。

表格“状态”列显示“正在更新”“查询失败”“不存在”，正常空闲时显示“上次核对: <时间>”，停用目标显示“已停用”。失败和不存在为当前 GUI 会话的最新结果，重启后从本地历史恢复上次核对时间。

GUI 不需要另开 CLI 进程。启用的通知通道会按现有告警策略真实发送，请先确认 notify 配置。CLI 循环间隔仍由 --watch 指定。浏览器路径留空为自动查找，无头模式关闭时显示 Cookie 引导窗口。

自动检测按安装路径的文件存在性选择浏览器：Win7 优先 Supermium，其他系统优先 Edge，找不到时保留 Chrome / Chromium 后备。同一浏览器内按版本目录选择，不跨品牌比较版本。支持 Program Files、用户级安装与 EdgeCore 版本目录，包括 `C:\Program Files\Supermium\chrome.exe`。监听设置显示检测结果并可重新检测；路径留空保持自动模式，不把本机路径写入配置。手动路径优先且失效时报错，不静默切换。找到文件不代表已验证启动、CDP 或站点查询兼容性；360 系浏览器尚未列为已支持。

## GUI 通知与测试

“通知与测试”页支持 Windows、钉钉、企业微信、飞书、通用 webhook 和邮件。渠道卡片默认收起，展开后查看配置摘要、编辑或测试。新增、编辑、启停和删除立即保存；触发状态、连续错误阈值、冷却时间和每批目标告警数量需点击“保存触发策略”。

GUI 的扫描与通知分别在后台线程执行。扫描结束即开始下一轮倒计时，不等待通知停留或网络推送。各轮报告连同当时的通知配置按顺序排队，通知慢时可能积压；隐藏至托盘不会清空队列，明确退出程序会等待扫描和待发通知结束。队列只保存在内存中，强制结束进程或断电会丢失尚未发送的报告。
同轮所有符合触发策略和冷却条件的目标均参与告警。`alert_max_per_cycle` 保留旧配置字段名，但现在表示每批目标数量，超过时继续分批，不再舍弃后面的目标；普通 Windows 通知长正文也会拆分发送，避免截断后面的 ETB/ETD 变化。

测试可发送到单个选中渠道或全部启用渠道，确认后真实推送。仅使用已保存配置，不查询船期、不受触发条件与冷却限制，也不更新告警冷却记录。未配置目标时也可测试；停用渠道不发送。测试期间锁定配置编辑并暂缓自动查询，完成后继续倒计时调度。关闭时须等待后台推送结束。

机器人地址、加签密钥和邮件密码默认遮罩；测试结果脱敏并按纯文本显示。凭证仍以明文保存在本地 watchlist.json，勿提交或分享。Windows 通知需要交互式桌面会话；邮件默认使用 SSL，非 SSL 模式在服务器不支持 STARTTLS 时可能明文发送。推送成功后仍需确认收件端是否收到。

Windows 渠道可独立开启“保持显示”。开启后停留时间输入禁用，原秒数保留；通知改用置顶、非阻塞的程序浮窗，多条消息合并显示，直到手动关闭或退出程序。主窗口最小化不会收起浮窗。关闭开关后恢复系统通知，其实际停留时间由 Windows 决定，秒数控制托盘消息处理时长。配置字段为 `persistent`（默认 `false`），保持显示仅支持 GUI；CLI 会报告该渠道发送失败，不会无限等待。

至少选择一种触发状态；暂停通知请停用所有渠道。心跳及停摆等未展示的设置字段保持原值，可继续在配置文件中维护。

保存仅更新页面支持的 settings 字段，保留目标、通知和其他配置。GUI 内两个配置页同步文件快照；外部编辑后须重新加载，避免覆盖。

新增和编辑时去除首尾空白；同类型目标按名称不区分大小写去重，停用目标也参与检测。显示名称仅影响展示。删除需要确认，不删除查询历史；修改查询名称或类型后建立新的比较基线。

查询进行中暂不可修改目标。保存保留其他查询设置、通知配置和注释字段；若文件已被外部修改，请点击“重新加载”后重新编辑。首次创建的配置没有通知通道，可后续通过配置文件设置。

## 源码运行

主环境为 Python 3.8、PySide2 / Qt 5.15。安装对应依赖后复制配置：

```bat
python -m pip install -r requirements.txt
python -m pip install -r requirements-gui.txt
copy watchlist.example.json watchlist.json
python run_monitor.py
python -m gui.app
```

修改 targets：ship 按船名查询，voyage 按码头航次查询。船名建议填写完整，以减少子串匹配。

```bat
python run_monitor.py --watch 1800
python run_monitor.py --no-notify
python run_monitor.py --test-alert
python run_monitor.py --dump-html snapshots
python tools/env_check.py --browser C:\Supermium\supermium.exe
```

--test-alert 会真实发送通知；env_check 会启动浏览器并访问站点。--dump-html 仅保存首分页 HTML。--show-browser 显示 Cookie 引导窗口，--verbose 显示调试日志。
退出码：0 无变更、10 有变更、1 配置或通道错误、3 查询失败。

## 配置与通知

配置见 [watchlist.example.json](watchlist.example.json)。旧 token 与 settings.precheck 被忽略，通过 AppConfig 保存时不再输出；GUI 目标管理仅修改 targets，不清理其他字段。旧 --token、--no-auto-renew 参数与续期工具已移除。
通知支持 Windows、钉钉、企业微信、飞书、webhook 和邮件。默认在变更、未查到及连续错误达到阈值时告警，首次查询用于建立基线。Windows 通知需要已登录的交互式桌面会话；无人值守可配置邮件或 webhook。

stale_after_hours 在恢复运行时检测长时间未成功查询；heartbeat_hours 定期发送运行消息。进程停止后两者都不能自行告警。heartbeat_url 可接入外部心跳服务，由外部服务检测停止。
watchlist.json 可能包含凭证，勿提交或分享。Git 忽略和打包排除不能代替实际交付检查。

## 查询与本地数据

默认起始日为今天减 7 天，max_pages 限制查询分页。state/ 保存状态，每个航次最多保留 200 条观察记录；.cache/ 保存 Cookie，.browser_profile/ 保存浏览器配置，snapshots/ 为可选快照。这些运行数据不随源码交付，清理前确认是否需要保留历史。
会话失效时重引导 Cookie 并重试一次；HTTP 429、503、567 采用退避重试。首个目标发生会话、网络或限流错误时，本轮跳过后续目标。

## Windows 7 与交付

Win7 使用 Python 3.8 和兼容浏览器，依赖见 requirements-win7*.txt。[实机验证指南](docs/Win7-实机验证指南.md) 列出现场检查步骤；本轮静态清理不构成新的实机验证。

Linux/LoongArch GUI 仍处于试验阶段。Linux 启动前会直接选择 PySide6，不导入 PySide2；Windows 仍优先 PySide2，保持 Win7 路线。AOSC 试验机可使用发行版提供的 PySide6、aiohttp、Chromium，并在复用系统包的虚拟环境中安装 `PySide6-Fluent-Widgets`。不要在同一环境安装两种绑定版本的 Fluent Widgets。Qt/Fluent 离屏窗口已单独验证；本程序的完整页面、托盘、浏览器引导与 Linux 打包尚未验收。

tools/make_bundle.py 生成源码交付包，tools/build_gui.py 和 tools/build_release.py 用于构建程序。

两条 GUI 构建路径共用资源、隐藏导入和依赖版本元数据配置，并在构建后检查图标、Logo、许可文件及 SVG/JPEG 插件。完整现场包的离线 wheels 包含 GUI 依赖。交付须复制整个 onedir 文件夹，不能只复制 EXE。资源检查不等于运行验证：发布前仍须在无开发环境依赖的机器上检查页面、通知和浏览器引导，确认与源码运行效果一致。
