# Win7 实机验证指南

> 目的：在**真正的那台 Win7 机器**上，确认方案是否成立。

## 当前进度（2026-09-14 更新）

| 环节 | 状态 |
|---|---|
| Win7 机器上的浏览器能否打开站点 | ✅ **已确认能打开** —— 最关键的未知已排除 |
| 项目文件复制到 Win7 | ⚠️ 曾报 `No module named 'ytmon'`（文件没复制全，见第 0 步） |
| 告警通道 | ✅ 已在现代机上端到端验证（含真实 HTTP 发送） |
| Python 3.8 环境 | 待确认 |
| 完整自检（含 cookie 引导） | 待跑 |
| 告警通道在 Win7 上实际发送 | 待跑（第 5 步） |

> **结论：Win7 路线成立**，剩下的是把环境搭起来。
> 下面的第 0 步和第 2 步是你现在要做的；第 3 步（浏览器能否过挑战）**你已经验证过了**。

---

## 为什么必须先做这个

Win7 上有三个硬约束（详见 `docs/GUI-技术选型与基座.md`）：

| 约束 | 结论 |
|---|---|
| Qt 6 不支持 Win7 | GUI 必须用 **Qt 5.15（PySide2）** |
| Python 3.9+ 不支持 Win7 | 运行时必须用 **Python 3.8** |
| Edge 最高只能到 109（已 EOL） | 需要 **Supermium**（Chromium 138 内核的 Win7 分支） |

前两条是**确定的**（有官方文档），第三条是**待验证的**：
Supermium 能不能过腾讯 EdgeOne 的挑战，只有实机跑过才知道。

**如果第三条不成立，整个 Win7 路线就要重新设计** —— 所以先花 15 分钟验证，别先写代码。

## 第 0 步：把项目拷到 Win7 机器

### 推荐做法：用打包脚本（避免手工挑文件出错）

在开发机上执行：

```powershell
python tools\make_bundle.py
```

会生成 `dist\ytmon-<日期>.zip`（约 120 KB）。该脚本会：
- 按固定清单收集文件，**不会漏掉 `ytmon/` 目录**
- **自动扫描压缩包里有没有真实凭证**（船期 token、钉钉/企微/飞书机器人密钥、
  明文邮箱密码），扫到就中止打包
- **不含 `watchlist.json`**（那里面有告警通道的密钥）

把 zip 拷到 Win7，解压到例如 `C:\ytmon\`，然后确认结构：

```
C:\ytmon\ytmon\__init__.py      ← ytmon 包必须在根目录下
C:\ytmon\tools\env_check.py
C:\ytmon\run_monitor.py
```

### ⚠️ 如果你看到 `No module named 'ytmon'`

**这就是"文件没复制全"**，不是代码问题。最常见的原因：

- 只复制了 `tools\env_check.py`，没带上整个 `ytmon\` 目录
- 解压后目录**多套了一层**，而运行目录不是项目根

**确认方法**——在项目根目录执行：

```bat
dir
```

必须能看到 `ytmon` 这个**目录**（不是文件）。若看不到，就把 `ytmon\` 目录补过来。

**最省事的解法**：用上面的 `make_bundle.py` 打包，把 zip 整个解压，
不要手工挑文件。自检工具现在也会在最开头就检查这一点并在缺失时直接告诉你。

## 第 1 步：确认 Python（不需要装任何依赖）

Win7 上能用的最后一个 Python 是 **3.8.10**（官方安装包版本号就到 .10）。

- 下载：<https://www.python.org/downloads/release/python-3810/> 里的
  `Windows installer (64-bit)` → `python-3.8.10-amd64.exe`
- 安装时**勾选 `Add Python 3.8 to PATH`**
- 如果装完报缺 `api-ms-win-crt-*.dll`，先装微软的 **KB2999226**
  （Universal C Runtime，Win7 装 Python 3.5+ 的前置条件）

装好后打开命令提示符验证：

```bat
python --version
```

应显示 `Python 3.8.10`。

> **本步不需要 pip install 任何东西。** 自检工具的前 6 步只用标准库。

---

## 第 2 步：先跑一次自检（关键一步，此时还没装浏览器）

```bat
cd /d <项目目录>
python tools\env_check.py
```

**期望输出**（这台开发机上的样子，供对照）：

```
  [✓] 环境: Python 3.8.10 · Windows 7 6.1.7601 (6.1.7601) · AMD64  ← Win7 路径
  [✓] DNS: www.156yt.cn → 171.105.220.186, ...
  [✓] TCP: 443 端口可连通
  [✓] TLS: TLSv1.2 · ECDHE-RSA-AES256-GCM-SHA384
  [✓] 证书: CN=*.156yt.cn 签发者=GlobalSign nv-sa 到期=...
  [!] 站点: HTTP 200，返回的是 EdgeOne JS 挑战页（纯 HTTP 客户端被拦，属预期）
  [✗] 浏览器: 没有找到可用的 Chromium 系浏览器
```

### 这一步要看的三个重点

1. **`TLS` 那一行** —— Win7 最常见的坑是协商到 `TLSv1`/`TLSv1.1`，或者证书校验直接失败
   （Win7 根证书库太旧）。**如果这行是 `[✓] TLSv1.2`，说明网络层没问题。**
2. **`站点` 那一行是 `[!]` 而不是 `[✗]`** —— 被挑战页拦住是**正常的、预期的**，
   因为纯 HTTP 客户端本来就会被拦，这正是需要浏览器的原因。
3. **`浏览器` 是 `[✗]`** —— 正常，下一步装。

> 如果 TLS 这步就失败了，**先停下来**：把 `[✗]` 那两行的完整文字发我，我们再决定。

---

## 第 3 步：装 Supermium（Win7 上的浏览器）

Supermium 是内核跟进到 **Chromium 138** 的 Windows XP/7 分支，Chromium 系所以 CDP 可用。

1. 打开 <https://github.com/win32ss/supermium/releases>
2. 选最新的 **Windows 7 x64** 版本（文件名含 `win7` 或 `x64`）
3. 解压到例如 `C:\Supermium\`，确认里面有 `supermium.exe`

**先手动试一下（这是最直观的验证）：**

用 Supermium 打开：

```
https://www.156yt.cn/pqs_revision/pages/jsp/popuPublic.jsp?loginVerifyCode=
```

| 看到什么 | 含义 |
|---|---|
| 正常显示「集装箱公众查询」页面 | ✅ **能过挑战**，方案成立 |
| 页面空白 / 一直转圈 / 提示验证 | ❌ 挑战没过，**请停下来告诉我** |
| 提示证书错误 | ⚠️ Win7 根证书问题，告诉我 |

## 第 4 步：装依赖并跑完整自检

```bat
python -m pip install -r requirements-win7.txt
python tools\env_check.py --browser "C:\Supermium\supermium.exe"
```

> **不需要 token，也不需要账号。** 实测确认公众船期查询**不带 `loginVerifyCode`
> 参数都能查**（见 `RECON-盐田船期.md` 第 2.4 节），所以自检不会要求你填任何凭证。

**期望**：`[✓] 浏览器` → `[✓] 引导`（成功拿到 `EO-Bot-Js-Token`）。

```
  [✓] 浏览器: C:\Supermium\supermium.exe
        （启动浏览器中，约 10-30 秒…）
  [✓] 引导: 成功拿到 cookie：JSESSIONID, EO-Bot-Js-Token（长度 683）
```

**最后跑一次真正的监控**（这是最终验收）：

```bat
python run_monitor.py
```

期望看到每个目标一行 `[无变化]` 或 `[首次]`，并以
`—— 本轮结束：变更 N / 首次 N / 无变化 N / 未查到 N ——` 收尾。

- 如果 `引导` 失败 → 把完整报错发我；可加 `--show-browser` 观察窗口里的实际情况
- 如果 `浏览器` 探测不到（便携版在非标准目录）→ 用 `--browser` 显式指定

## 第 5 步：验证告警通道（Win7 上最该单独测的一步）

监控能查到变化，但**通知发不出去**等于白做。而在 Win7 上，这一环的坑比监控逻辑本身多：
内网代理要有、机器人可能已被移出群、SMTP 端口可能被封、Win7 的 TLS 栈可能握不上手。

所以**单独测**，别等真出事才发现通知是哑的。

先编辑 `watchlist.json`，在 `notify` 数组里填一个通道（写法见 `watchlist.example.json`），然后：

```bat
python run_monitor.py --test-alert
```

**期望输出**：

```
—— 告警通道自检 · 2 个通道 ——
    钉钉（dingtalk，启用）→ https://oapi.dingtalk.com/robot/send?access_token=%2A%2A%2A
    邮件（email，启用）→ smtp.example.com

  [✓] 钉钉
  [✓] 邮件

—— 成功 2 / 2 ——
```

几点说明：

- 显示的地址里 `access_token` / `key` 会被打码成 `***`，可以放心截图
- 失败一条不影响其他条，会逐条报错（例如 `ConnectionError` / `SMTPAuthenticationError`）
- 退出码 `0` = 全部成功，`1` = 有通道失败
- **先只配一个通道测通，再加第二个。** 一次配五个然后全失败，很难定位

> 如果钉钉/企微返回 `errcode` 非 0，程序会把它当失败报出来 ——
> 这类接口即使出错也回 HTTP 200，只能看响应体，代码里已经处理了。

### 建议的监控频率

**30 分钟一轮就够**（`--watch 1800` 或计划任务 30 分钟一次）。

实测站点会限流：短时间连续请求会返回非标准状态码 `567`，偶发还会把会话弹回首页。
程序有自愈（重引导 cookie + 重试），但**你探得越急，越容易把自己推进降级窗口**，
反而更容易误报"查询失败"。船期变动本来就不是秒级事件，没必要盯那么紧。

## 附：常见报错对照

对着 `[✗]` 那一行的原文找：

| 报错原文 | 真正的原因 | 怎么办 |
|---|---|---|
| `No module named 'ytmon'` | 文件没复制全 | 用 `make_bundle.py` 重新打包，整个解压（第 0 步） |
| 浏览器那行说"没有找到可用的 Chromium 系浏览器" | Supermium 不在已知扫描路径里 | 用 `--browser "C:\Supermium\supermium.exe"` 显式指定 |
| 浏览器那行说"**路径存在但启动不了**"，并提到 `WinError 2` / 运行时库 | 缺 VC++ 运行库，或只挑了个 exe 出来没整包解压 | 装 `vc_redist.x64.exe`；确认是整个压缩包解压的 |
| **查询**那行报 `FileNotFoundError: 未找到任何 Chromium 系浏览器` | 第 9 步（查询）在重新引导 cookie 时**没拿到第 7 步指定的路径** | **已修（2026-09-14）**，见下 |

### 关于最后一条

这个 bug 很隐蔽，值得记一笔：

第 7 步用 `--browser` 指定了 Supermium，第 8 步（引导）用的也是它，
但第 9 步（查询）**没把这条路径传下去** —— 查询那步在需要重新引导 cookie 时
会退化成"自动探测浏览器"，在 Win7 上（Supermium 装在非标准目录）必然失败。

更绕的是它还叠了第二层原因：第 8 步当时直接调 `_bootstrap_async`，
**没把 cookie 写进缓存**，于是第 9 步必定需要重新引导 —— 一定踩中上面那个坑。

用户看到的是"第 7 步明明通过了，查询却说找不到浏览器"，两句话完全对不上。

在开发机上永远复现不出来：那里 Edge 能被自动探测到，而且缓存往往已经在了。
**只有在"新机器 + 浏览器装在非标准目录 + 没有 cookie 缓存"三者同时成立时才暴露**——
正好就是 Win7 首次验证的场景。

现已修：第 9 步接上路径，第 8 步改走 `bootstrap_cookies`（会写缓存）。
`tests/test_env_check.py` 用"把自动探测打成返回空"的手法精确复现过这个场景。

## 附：如果浏览器过不了 EdgeOne 挑战

浏览器过不了挑战，不代表项目做不了，但 Win7 这条路要换设计。可选：

| 方案 | 说明 |
|---|---|
| **服务跑在现代机器** | 抓取在有 Edge 的机器上跑，Win7 只做展示（走本地 HTTP/文件）。最稳。 |
| **官方船期信息订阅接口** | 平台自己提供推送接口（`/clearance2/clearanceValueAdd.action` 可申请开通），不需要浏览器，也不需要绕过任何防护。**这其实是长期最正确的路。** |
| Edge 109 而不是 Supermium | 若机器上已有 Edge 109，先用 `--browser` 指过去试一次（但 109 已 EOL，不推荐长期用） |

## 附：Win7 上还能用到的东西

- **pywinstyles 帮不上忙**：它的机制是 Windows 10/11 专有的 DWM 属性，
  样式表里那个 `win7` 是"在 Win11 上伪装成 Win7 外观"，不是"支持 Win7"。
  （详见 `docs/GUI-技术选型与基座.md` 第 0.1 节）
- **Python 3.8 已 EOL**（2024-10，无安全更新）。你已确认内部工具可接受。
- 业务代码**不需要为 3.8 改动**：已逐文件核对 26 个 `.py`，
  只用 3.8 就支持的语法与 API（无 `list[str]` 之类内建泛型下标、
  无 `match`、无 `X | Y` 运行时类型运算）。新加的 `notify.py` 也一样，
  并且它**不引入任何新依赖** —— 这是刻意的，就是为了不给 Win7 加风险。
